# 需求规格说明书（Spec）: f_matcher 在超大文件量场景下的性能优化重构

依据：`intent.md`（Finalize）。状态：Finalize |

## 1. 范围

对 `toolkit/f_matcher` 做一次**行为等价**的性能重构：在不改变匹配语义、输出格式与退出码的前提下，把"文件数量超大"场景下的端到端耗时从 2.26s（2 万文件 / 79MB）压到 0.30s 以内。

不在本次范围：正则/模糊匹配、UTF-16 支持、命中行原文回显、增量扫描与结果缓存、GUI、多目录扫描、与 `rts-center` 集成、修改被扫描文件。

## 2. 命令行接口

```text
f_matcher <dir> [--rule <rule-file>] [--jobs N]
f_matcher --help
f_matcher --version
```

| 参数 | 语义 | 取值 | 默认 |
|------|------|------|------|
| `<dir>` | 待扫描目录（必填） | 路径 | — |
| `--rule <file>` / `--rule=<file>` | 关键字规则文件 | 路径 | 可执行文件同级 → 源码树同名文件 |
| `--jobs <n>` / `--jobs=<n>` | 并发工作线程数 | 正整数 | `available_parallelism()` |

**新增 `--jobs` 的行为约定：**

- `n >= 1`，非法取值（0、负数、非数字）→ stderr 提示 + 打印用法 + 退出码 **1**（与既有参数错误一致）。
- `n = 1` → 串行执行，行为与优化前完全一致（可作为线上排障时的退路）。
- `n` 大于实际并发收益时，超出部分不额外创建线程（实现上以"最多 n 个线程"为上限）。
- `--jobs` 不影响输出内容与顺序（见 §6 确定性要求）。

`--help` 输出需补充 `--jobs` 说明与"并行扫描"的行为描述。

## 3. 匹配语义（不变量）

重构**只允许改变实现方式**，以下语义一条不得漂移：

1. **关键字表**：取规则文件中 `关键字` 标签行的内容，按半角/全角逗号切分，去首尾空白、丢弃空项、去重（保留首次出现顺序）。
2. **排除词表**：取规则全文中成对引号包裹的片段（全角弯引号 `“…”`、半角双引号 `"…"`、半角单引号 `'…'`），去空白、丢弃空项、去重。
3. **匹配粒度**：逐行匹配，行的定义 = 按 `\n` 切分，行尾 `\r` 不参与匹配（CRLF 兼容）；文件末尾无换行时最后一段也算一行；行号从 1 开始。
4. **排除判定（严格紧邻）**：关键字匹配位置之后**紧接**的字符，若构成某个排除词（以该位置为起点的前缀匹配），该次匹配**不计为命中**。
   - `部队医院` → 不命中；`解放军总医院` → 命中；`医院旁边的部队` → 命中（排除词在前不影响）。
5. **命中即停**：某行命中即认为该文件命中，**立即终止该文件后续匹配**，该文件只产出一条结果。
6. **同行多命中**：取**起始位置最靠前**的有效命中作为该行的命中（位置用于判定对象，输出不需要）。
7. **同一关键字的重叠出现**：同一关键字在行内的多次出现，按**非重叠**方式依次判定（等价于 `str::match_indices` 语义）；不同关键字之间允许重叠判定。
8. **大小写敏感**，精确字面匹配。

## 4. 编码语义（不变量）

1. 文件以 **UTF-16 BOM**（`FF FE` / `FE FF`）开头 → 报 `Unsupported`，该文件记为"覆盖不完整"（影响退出码）。
2. 文件**整体**是合法 UTF-8 → 按 UTF-8 处理（首行前 3 字节的 UTF-8 BOM `EF BB BF` 需剥离）。
3. 否则按 **GB18030**（兼容 GBK/GB2312）解码。
4. 判定依据是**整个文件的 UTF-8 合法性**，不是"前 N 字节采样"（保持与既有实现一致的结果）。

## 5. 扫描范围与遍历语义（不变量）

1. 递归遍历 `<dir>` 下所有层级；只处理扩展名为 `.txt` / `.csv` 的文件（大小写不敏感）。
2. **不跟随目录符号链接**（避免环路）；指向普通文件的符号链接按目标内容扫描。
3. 规则文件自身若位于待扫描目录内，**跳过不扫**。
4. 遍历过程中的目录读取失败等，收集为告警（stderr 输出），并使退出码为 2（覆盖不完整）。

## 6. 输出与确定性（强化要求）

1. stdout 每行一条 `<绝对路径>:<命中行号>`，格式与优化前逐字节一致。
2. **确定性**：命中清单按**路径字典序**输出；告警按路径排序后输出。并发度、线程调度、文件遍历顺序都**不得**影响输出内容与顺序。
3. stderr 告警内容不包含文件内容片段。
4. 退出码：`0` 无命中 / `1` 参数·目录·规则文件错误 / `2` 扫描完成但覆盖不完整 / `3` 至少命中一个文件；**2 优先于 3**。

## 7. 性能需求

| 编号 | 需求 | 度量方式 |
|------|------|---------|
| P1 | 20k 文件 / 79MB 数据集端到端 ≤ **0.30s** | 固定数据集，重复 3 次取中位数 |
| P2 | UTF-8 文件每个只被**读取一次** | 代码走查 + 性能计数 |
| P3 | 每行文本对关键字只做**一遍**扫描 | 代码走查（单遍多模式匹配） |
| P4 | 扫描与目录遍历均为**多核并行** | `time` 的 CPU 占用 > 100% |
| P5 | 内存占用不随文件总数线性膨胀 | 峰值 RSS 观测 |

## 8. 模块划分

| 文件 | 职责 |
|------|------|
| `src/main.rs` | 入口：参数 → 规则 → 目录 → 并行扫描 → 有序输出 → 退出码 |
| `src/cli.rs` | 参数解析（新增 `--jobs`）、用法文本、规则文件路径解析 |
| `src/rule.rs` | 规则文件解析；多关键字匹配器构建与逐行命中判定 |
| `src/scanner.rs` | 目录遍历（并行）、文件读取与编码识别、逐行匹配编排 |

新增依赖：`aho-corasick`（多模式单遍匹配）、`rayon`（数据并行与并行遍历）。不引入 `thiserror`/`anyhow`/`clap`，保持错误类型手写、依赖树精简。

## 9. 行为规格（用例）

| 编号 | 场景 | 期望 |
|------|------|------|
| B1 | UTF-8 文件，第 2 行命中 | 输出 `路径:2`，退出码 3 |
| B2 | GB18030 文件命中 | 输出正确行号，退出码 3 |
| B3 | UTF-8 BOM 文件 | BOM 不影响匹配与行号 |
| B4 | UTF-16 BOM 文件 | 报不支持，退出码 2 |
| B5 | 关键字紧邻排除词 | 该次不命中 |
| B6 | 排除词不紧邻 | 仍命中 |
| B7 | 同一文件多次命中 | 只输出第一条（最早命中行） |
| B8 | 文件末尾无换行 | 末段计入行号 |
| B9 | CRLF 行尾 | 行号正确，`\r` 不参与匹配 |
| B10 | 规则文件位于被扫描目录内 | 规则文件本身不被报为命中 |
| B11 | 非 `.txt`/`.csv` 文件 | 不扫描 |
| B12 | 目录符号链接 | 不跟随，无死循环 |
| B13 | 某个文件不可读 | 告警到 stderr，其余文件照常扫，退出码 2 |
| B14 | `--jobs 1` 与 `--jobs 20` | 输出逐字节一致 |
| B15 | 优化前后同一数据集 | 输出与退出码逐字节一致 |
| B16 | `--jobs 0` / `--jobs abc` | 参数错误，退出码 1 |

## 10. 与现有约束的冲突

- **§4.4 与性能优化 P2 存在张力**：单遍读取要求"读一次文件"，而"整文件 UTF-8 合法性"判定要求在报告命中前确认文件整体合法。**裁定**：采用"单遍流式读取 + 命中后继续读完以确认合法性 + 发现非法字节则回退重扫"的方式——UTF-8 文件（主流）只读一次，GB18030 文件在首个非法字节处中断后重扫一次。该路径对**任何文件**的判定结果与优化前**完全一致**。
- **§3.7 的非重叠语义 vs 单遍多模式匹配的天然重叠**：多模式匹配器返回的重叠结果需按 §3.7 规则归一（同关键字丢弃被前一次匹配覆盖的出现），以保持与 `match_indices` 等价。
