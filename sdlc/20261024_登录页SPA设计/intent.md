# 意图（Intent）: RTS 搬运工 Web 控制台登录页（SPA）

Author: 发起人（仓库 owner）. 状态：Final

## 问题（Problem）

`web-ui` 目前只有一个 Vite + React 的脚手架模板，没有任何业务页面，也没有构建产物进入团队的日常使用路径。rts-center 作为平台资源访问的对外 REST 门面，后续要承载任务调度监控、链路状态查看等界面，但当前：

- 没有前端入口界面，用户无法通过浏览器进入平台；
- 没有任何身份认证入口，未来的写操作接口缺少统一的登录与凭证承载点；
- 没有前端路由骨架，后续页面无法组织成 SPA，也无法对受保护页面做前置拦截。

## 预期结果（Proposed outcome）

交付一个可运行的 Web 登录入口，满足：

1. **登录页**：左侧深色品牌展示区 + 右侧浅色登录表单的双栏布局；表单包含用户名、密码、记住我、忘记密码入口、登录按钮，提交时有明确的校验反馈（空值、账号不存在、密码错误、账号锁定等状态）。
2. **路由与守卫**：引入 SPA 路由，`/login` 为登录页，`/`（首页/概览）为受保护页面；未登录或凭证过期时自动跳转 `/login` 并携带来源路径，登录成功后跳回原来源页；已登录访问 `/login` 时重定向到首页。
3. **接口契约**：给出认证相关的 REST 契约与 TypeScript 类型定义；前端以 mock 实现该契约，通过一个开关即可切换到真实后端，无需改动页面代码。
4. **可验证**：`bun run build`、`bun run lint` 通过；`bun run dev` 启动后可在浏览器中走通「未登录访问首页 → 跳登录 → 登录成功 → 回到首页」的完整闭环。
5. **设计基线沉淀**：沉淀一套可复用的前端设计令牌与基础组件（Tailwind 主题令牌 + shadcn 风格 UI 基础件），后续页面沿用同一套视觉语言。

度量：上述 5 条全部可演示通过，且后续新增页面不再重复搭建主题与表单基础设施。

## 受影响的模块（Affected modules）

| 模块 | 路径 | 影响 |
|----|----|----|
| 前端工程 | `web-ui/`（新增并纳入版本管理） | 全新脚手架接入 Tailwind、路由、表单校验，构建与 lint 配置 |
| 前端页面 | `web-ui/src/pages/`、`web-ui/src/components/` | 登录页、品牌区、占位首页、表单与基础 UI 组件 |
| 前端路由 | `web-ui/src/routes/`、`web-ui/src/auth/` | SPA 路由表、路由守卫、登录态存取与凭证生命周期 |
| 接口契约 | `web-ui/src/api/` | 认证 REST 契约、TS 类型、mock 实现与真实后端切换开关 |
| 设计令牌 | `web-ui/src/styles/`、`web-ui/src/index.css` | Tailwind 主题令牌、明暗主题变量、基础样式 |

后端 `server/rts-center` 本次**不改动**：仅约定接口契约，后端实现另行排期。

## 约束条件（Constraints）

- **技术栈**：沿用 `web-ui` 现有脚手架（Vite 8 + React 19 + TypeScript），包管理使用 `bun`；样式走 Tailwind CSS 方案，组件走 shadcn/ui 风格（Radix 原语 + 变体模式），不引入重量级 UI 框架。
- **不引入不必要依赖**：仅在确有需要时添加依赖（路由、表单校验、图标、类名合并工具等），避免为单个页面堆砌依赖。
- **安全**：密码字段不做持久化存储；`localStorage` / `sessionStorage` 中只放凭证与最小化的用户信息；不得把密码写进日志或错误提示。
- **可访问性**：表单控件必须带可关联的 label，错误提示通过 `aria-invalid` / `aria-describedby` 暴露给辅助技术；全流程键盘可达，焦点可见。
- **兼容性**：跟随 Vite 默认的现代浏览器基线（ES2023），不做 IE 兼容。
- **明确不做**（本次范围外）：
  - 不实现后端认证接口、不实现用户管理、角色权限、注册与找回密码流程；
  - 不做移动端原生 App、不做国际化多语言（本次界面文案固定为中文）；
  - 不做真实监控数据的可视化首页（首页仅为占位骨架）。

## 未解决问题（Open questions）

- 认证契约的具体字段（用户名是否唯一标识、是否需要租户/环境字段、令牌形态、错误码枚举）——由 `spec.md` 给出建议默认值，最终以发起人评审结论为准。
- 凭证存放策略：`localStorage`（配合「记住我」）与 `sessionStorage`（不勾选）的切换规则——由 `spec.md` 定义。
- 页面是否需要同时提供明/暗双主题切换——本次仅做「左深右浅」的单主题，浅色表单区固定为浅色。
