# 需求规格说明书（Spec）: f_matcher 批量扫描目录下命中敏感关键字的文件

依据：`intent.md`（Finalize）。状态：Draft，待发起人评审 |

## 1. 范围

交付一个独立命令行工具 `f_matcher`：接收一个待扫描目录，递归遍历其下所有 `.txt` / `.csv` 文件，按 `sensitive_rule.txt` 中定义的关键字与排除规则逐行匹配，命中即停（每文件只报首个命中），向 stdout 输出命中文件的绝对路径与命中行号。

不在本次范围：正则/模糊匹配、命中行原文回显、命中统计报表、UTF-16 支持、GUI、多目录批量扫描、与 rts-center 集成、修改被扫描文件。

## 2. 命令行接口

```text
f_matcher <dir> [--rule <rule-file>]   # <dir> 必填；--rule 可选
f_matcher --help                        # 打印用法（含规则说明、输出格式、退出码表）后退出 0
f_matcher --version                     # 打印版本后退出 0
```

| 情形 | 行为 | 退出码 |
|------|------|--------|
| 目录不存在 / 不是目录 / 不可读 | stderr 提示原因 | 1 |
| 规则文件不存在 / 不可读 / 解析不出关键字 | stderr 提示原因 | 1 |
| 参数非法（缺目录、多余位置参数、未知选项） | stderr 打印用法 | 1 |
| 扫描完成，无命中 | stdout 无输出 | 0 |
| 扫描完成，至少命中 1 个文件 | stdout 输出命中清单 | 3 |
| 扫描完成，但存在文件读取失败（覆盖不完整） | stdout 输出已命中的清单 + stderr 告警 | 2 |

- 参数解析手写实现，不引入 clap（保持依赖树精简）。
- `--rule` 未指定时的规则文件查找顺序（先命中者生效）：
  1. 可执行文件所在目录下的 `sensitive_rule.txt`；
  2. 编译期 `CARGO_MANIFEST_DIR` 下的 `sensitive_rule.txt`（源码树内直接 `cargo run` 时可用）。
  两者都不存在 → 报错退出 1。
- 退出码 2 与 3 的优先级：扫描不完整（2）优先于命中（3）？**判定：命中且不完整 → 2；仅不完整 → 2；仅命中 → 3**。（即 2 > 3 > 0 的优先级在"不完整"情形下取 2。）

## 3. 规则文件格式与解析

### 3.1 当前规则文件内容

```text
关键字: 部队,军队,海军,空军,陆军,武装警察,军分区,解放军,导弹,武警,军部,司令部,雷达,潜艇,军用机场,总参,二炮,军需,弹药,军械,舰队,军工,警卫局,营区,军区

上述结果中，不包括“路”、“医院”、“宾馆”、“学院”、“家属区”、“宿舍”、“干休所”、“疗养院”，不包括的意思是上述关键后不能紧跟这些信息。
```

### 3.2 解析规则

1. 规则文件按 UTF-8 读取；读取失败或解码失败 → 报错退出 1。
2. **关键字表**：定位包含 `关键字` 标签的行，取标签后的内容，按 `,` 或 `，`（全角/半角逗号）切分，逐项去首尾空白，丢弃空项。
   - 标签与内容之间允许 `:` 或 `：`（全角/半角冒号）及任意空白。
   - 找不到关键字行，或切分后关键字表为空 → 报错退出 1。
   - 关键字按出现顺序保留，**去重**（保留首次出现的位置）。
3. **排除词表**：提取规则文件中所有成对引号包裹的片段作为排除词，引号支持 `“…”`、`”…”`（全角弯引号）、`"…"`、`'…'`（半角）。
   - 排除词去首尾空白、丢弃空项、去重。
   - 规则文件中没有引号片段时 → 排除词表为空（等价于不启用排除规则，不报错）。
4. 规则文件中的 `sensitive_rule.txt` 本身若位于待扫描目录内，**跳过不扫**（否则规则里的关键字会把规则文件本身报成命中）。

### 3.3 匹配语义

- 对文件的每一行文本，在该行内查找关键字的**字面出现**。
- **排除判定（严格紧邻）**：关键字匹配位置之后**紧接**的字符，若构成某个排除词（以该位置为起点的前缀匹配），则该次匹配**不计为命中**。
  - 例：行内容 `部队医院` → `部队` 紧接 `医院` → 不命中。
  - 例：行内容 `解放军总医院` → `解放军` 之后是 `总医院`，不以 `医院` 开头 → 命中。
  - 例：行内容 `军区干休所` → `军区` 紧接 `干休所` → 不命中。
- 同行内多个关键字、多个出现位置时，取**起始位置最靠前**的命中作为该行的命中（输出只需要行号，位置用于确定判定对象）。
- 某行命中即认为该文件命中，**立即终止该文件的后续匹配**（不再扫描该文件剩余行），该文件只产出一条结果。
- 大小写敏感（中文无大小写；规则中若含 ASCII 关键字则按原样精确匹配）。

## 4. 模块划分

| 文件 | 职责 | 关键类型 |
|----|----|----|
| `src/main.rs` | 入口：解析参数 → 编排扫描 → 输出结果 → 决定退出码 | — |
| `src/cli.rs` | 命令行参数解析、用法文本、规则文件路径解析 | `Cli { dir, rule }` |
| `src/rule.rs` | 规则文件解析与匹配判定 | `Rule { keywords, exclusions }`、`MatchResult` |
| `src/scanner.rs` | 目录遍历、文件读取、编码识别、逐行匹配编排 | `ScanReport`、`FileHit` |

错误类型：各模块自定义 `enum ...Error`（实现 `Display`），`main` 统一转成退出码与 stderr 提示；不引入 `thiserror`/`anyhow`。

## 5. 行为规格

### 5.1 目录遍历

- 递归遍历 `<dir>` 全部层级。
- **只处理**扩展名为 `.txt` / `.csv` 的文件（扩展名大小写不敏感，如 `A.CSV`、`data.Txt` 均命中）。
- 扩展名判定基于文件名最后一个 `.` 之后的部分；无扩展名或扩展名不匹配 → 跳过。
- **不跟随目录符号链接**（避免环路与越界）；文件符号链接按其目标内容正常扫描。
- 遍历顺序：按路径字典序排序，保证同一目录树下多次运行输出**完全一致**（可复现）。
- 隐藏目录/隐藏文件不做特殊处理（`.foo.txt` 会被扫描）。
- 目录不可读 → 该子目录整体告警并跳过（stderr），计入"扫描不完整"，不中断整体扫描。
- 待扫描目录本身不存在 / 不是目录 → 直接报错退出 1。

### 5.2 文件读取与编码识别

- 读取顺序：**先按 UTF-8 校验**，整文件合法 → 按 UTF-8 解码；否则回退 **GB18030**（兼容 GBK/GB2312）解码。
- 逐行读取（流式，不把整个文件读进内存）。
- **UTF-8 BOM**（`EF BB BF`）解码后从首行开头剥离。
- **UTF-16 BOM**（`FF FE` / `FE FF`）→ 本次不支持：stderr 告警并跳过该文件（计入扫描不完整）。
- 单个文件读取失败（权限、IO 错误）→ stderr 告警并跳过该文件，继续扫描其它文件，最终退出码 2。
- 匹配在**解码后的 Unicode 文本**上进行，避免多字节编码下关键字边界错位。

### 5.3 输出

- 每个命中文件输出一行：`<绝对路径>:<行号>`，行号从 1 开始，行尾一个 `\n`。
- 绝对路径 = 待扫描目录（经规范化/取绝对路径）+ 相对路径；路径中不做符号链接解析（保留目录树中的原始名字）。
- 输出**只含路径与行号**，不含命中行原文与命中关键字。
- 命中结果按遍历顺序输出（即路径字典序）。
- stdout 写入失败（如下游 `| head` 提前关闭管道）→ 静默结束，不 panic。

### 5.4 退出码

| 码 | 含义 |
|----|----|
| 0 | 扫描完成，无命中 |
| 1 | 参数 / 目录 / 规则文件错误 |
| 2 | 扫描完成但存在文件或子目录读取失败（覆盖不完整） |
| 3 | 扫描完成，至少命中 1 个文件（且无读取失败） |

## 6. 与既有约束的冲突 / 澄清

| 编号 | 事项 | 处置 |
|----|----|----|
| C1 | 关键字"命中即停"与"逐行匹配" | 明确为**每文件级**短路：首个命中行即终止该文件后续匹配，每文件只输出一条结果（依 intent 确认） |
| C2 | 排除词语义 | 采用**严格紧邻**判定（依 intent 确认）：关键字后紧接的字符构成排除词才算排除；"解放军总医院"仍算命中 |
| C3 | 编码 | UTF-8 优先、GB18030 回退（依 intent 确认），引入 `encoding_rs`（纯 Rust，无 C 依赖） |
| C4 | 规则文件放在 `toolkit/f_matcher/` 下，若待扫描目录包含它会自匹配 | 显式跳过规则文件本身（见 §3.2.4） |
| C5 | 输出含敏感内容 | 只输出路径与行号，不回显命中行原文与关键字（依 intent 确认） |
| C6 | `base/rts-core` 的 `logger` 目前是空壳 | 本工具体量小、行为确定，**不接入** rts-core 日志；错误与告警直接走 stderr 文本，避免引入不必要的依赖与日志噪音 |
| C7 | 退出码语义与 grep 不一致（grep 用 0 表示命中） | 本工具按"扫描任务"语义：0 = 无命中、3 = 有命中，便于 CI 中"无命中即通过"的直觉；同时 stdout 有输出可作为兜底判据（依 intent 确认） |

## 7. 依赖清单

| crate | 版本 | 用途 | 备注 |
|-------|------|------|------|
| `encoding_rs` | 0.8 | UTF-8 校验与 GB18030 解码 | 纯 Rust，无 C 依赖；由 crates.io 镜像拉取 |

`toolkit/f_matcher` 的其余能力（目录遍历、参数解析、字符串匹配）全部用标准库实现，不引入其它依赖。

## 8. 验证方式

### 8.1 单元测试（`cargo test`，无需外部数据）

`rule.rs`：

1. 规则文件解析：关键字 25 项全中、顺序正确；排除词 8 项全中。
2. 分隔符容错：半角 `,` 与全角 `，`；标签后全角/半角冒号与空白。
3. 排除词提取：全角弯引号、半角双引号、单引号三种形式。
4. 关键字去重；排除词去重；空项丢弃。
5. 无关键字行 / 关键字表为空 → 报错。
6. 匹配：命中（普通行）、紧邻排除（"部队医院"）、非紧邻（"解放军总医院"）、排除词不在关键字之后（"医院在部队之前"）→ 不排除、同行多关键字取最靠前位置、行尾无后续字符。

`scanner.rs`：

7. 目录遍历：只收 txt/csv（大小写不敏感）、递归子目录、跳过其它扩展名、跳过目录符号链接（不跟随）、按路径排序稳定。
8. 编码识别：UTF-8 文件与 GBK 文件中的同一中文关键字都能匹配上。
9. 命中即停：文件第 5 行命中时，不再看第 6 行的其它命中，只输出第 5 行行号。
10. 单文件读取失败 → 告警且不中断整体扫描。

`cli.rs`：参数个数校验、`--help`、`--version`、规则文件路径解析顺序。

### 8.2 手工验证

构造临时目录树：

```text
/tmp/fm_demo/
├── a.txt              # UTF-8，第 3 行含 "海军"（命中）
├── b.csv              # UTF-8，仅含 "部队医院"（紧邻排除，不命中）
├── c.txt              # GBK 编码，第 2 行含 "导弹"（命中，验证编码回退）
├── d.log              # 其它扩展名（跳过）
└── sub/
    └── e.csv          # 子目录，第 1 行含 "干休所"（不命中）、第 4 行含 "军区"（命中）
```

跑 `f_matcher /tmp/fm_demo`，确认输出恰为 `a.txt:3`、`c.txt:2`、`e.csv:4` 三行（绝对路径），退出码 3；再对无命中的目录验证退出码 0。

## 9. 不做（重申）

- 不做正则/模糊/同义词匹配，只按规则文件字面关键字匹配。
- 不输出命中行原文、命中关键字，不出统计报表。
- 不支持 UTF-16 编码文件（告警跳过）。
- 不做 GUI、多目录扫描、rts-center 集成。
- 不修改被扫描文件，不做删除/移动。
