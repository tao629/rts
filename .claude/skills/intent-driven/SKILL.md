# 处理流程

严格按照 **规划→设计→构建** 流程处理。

## 规划(Plan)

- 提出人用自己的话简要描述要实现的功能，想解决的问题；需要进一步追问涉及的范围、用户、限制条件以及期望达到的成功结果；**关键：不写怎么做，只写要解决什么问题、成功的标准、处理的边界范围**
- 参照下方 `intent.md` 模板撰写规划阶段产出物 intent.md 文件，初始状态为草稿（Draft），由提出人审阅无问题后设置状态为定稿（Finalize）

### intent.md模板

```markdown
# 意图（Intent）: 简要描述要实现的功能或待解决的问题

Author: <姓名/角色>. 状态：Draft |

## 问题（Problem）

<功能/需求要解决的问题，影响范围>

## 预期结果（Proposed outcome）

<完成的标识，需详尽说明，能度量最好>

## 受影响的模块（Affected modules）

<功能/需求实现涉及的模块、数据库表等>

## 约束条件（Constraints）

<安全、合规、性能、兼容约束；明确不做什么>

## 未解决的问题（Open questions）

<需进一步决策、拍板的事项>
```

## 设计(Design)

研读 `intent.md` 产出 `spec.md` 需求规范说明书，标记与现有约束冲突之处，由发起人评审。

### 注意事项

1. 明确边界：这里指写 `做什么`，不涉及 `怎么做`
