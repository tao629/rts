# f_matcher

批量扫描目录下命中敏感关键字的文件。

遍历指定目录下的所有 `.txt` / `.csv` 文件（含子目录），按 `sensitive_rule.txt` 中定义的
关键字规则逐行匹配；**一旦某文件命中 1 个关键字即终止该文件的继续匹配**；最终输出命中文件的
绝对路径与命中行号。

## 用法

```text
f_matcher <dir> [--rule <rule-file>] [--jobs <n>]
f_matcher --help
f_matcher --version
```

```bash
# 扫描 /data/export，规则文件用默认位置
f_matcher /data/export

# 指定规则文件
f_matcher /data/export --rule /etc/f_matcher/sensitive_rule.txt

# 限制并发线程数（默认按 CPU 核数；--jobs 1 表示单线程执行）
f_matcher /data/export --jobs 4
```

## 输出

标准输出每行一条，格式为 `<绝对路径>:<命中行号>`：

```text
/data/export/2026/批次1.csv:128
/data/export/2026/readme.txt:3
```

只输出路径与行号，**不回显命中行内容与命中关键字**，避免敏感内容二次扩散。

输出顺序与并发度无关：命中清单始终按路径字典序输出，告警按路径排序输出，
同一输入多次运行（含 `--jobs 1` 与多线程）结果完全一致。

## 扫描规则

| 项 | 说明 |
|----|------|
| 文件范围 | 递归遍历目录全部层级，只处理扩展名为 `.txt` / `.csv` 的文件（大小写不敏感） |
| 关键字来源 | 规则文件中 `关键字:` 标签行给出的词表，**不在代码中硬编码** |
| 排除语义 | **严格紧邻**：关键字后紧接排除词（路/医院/宾馆/学院/家属区/宿舍/干休所/疗养院）时该次匹配不算命中 |
| 编码 | UTF-8 优先识别，失败回退 GB18030（兼容 GBK/GB2312）；匹配在解码后的文本上进行 |
| 终止条件 | 每个文件命中 1 个关键字即停止该文件的匹配，每文件最多输出一条结果 |

排除语义示例：

| 行内容 | 结果 | 说明 |
|--------|------|------|
| `部队调动` | 命中 | 关键字后不是排除词 |
| `部队医院` | 不命中 | `医院` 紧跟在 `部队` 之后 |
| `解放军总医院` | 命中 | `总医院` 不以 `医院` 开头，不是紧邻 |

## 退出码

| 码 | 含义 |
|----|------|
| 0 | 扫描完成，无命中 |
| 1 | 参数 / 目录 / 规则文件错误 |
| 2 | 扫描完成但存在文件读取失败（覆盖不完整） |
| 3 | 扫描完成，至少命中 1 个文件 |

## 性能

目录遍历与文件扫描均为**并行**执行（默认线程数 = CPU 核数，可用 `--jobs` 调整）。
关键实现：

- **多关键字单遍匹配**：整张关键字表编译成 Aho-Corasick 自动机，每行文本只扫描一遍，
  而不是对 25 个关键字各扫一遍。
- **单遍读取**：UTF-8 文件只被读一次——读取、UTF-8 合法性校验与逐行匹配在同一次流式读取中完成。
- **零分配行切分**：GB18030 路径按字节缓冲切行，不逐行分配 `String`。

实测（20 核机器，release 构建，数据集为 2 万个 `.txt`/`.csv`、约 79MB 文本、命中率 1%）：

| 场景 | 优化前 | 优化后（多线程） | 优化后（`--jobs 1`） |
|------|--------|------------------|---------------------|
| 2 万文件 / 79MB | 2.25s | **0.07s**（约 32 倍） | 0.39s |
| 20 万文件 | 1.67s | **0.20s**（约 8 倍） | 0.99s |

## 依赖

| crate | 用途 |
|-------|------|
| `aho-corasick` | 多关键字单遍匹配（Aho-Corasick 自动机） |
| `memchr` | 字节流中快速定位换行符 |
| `rayon` | 目录遍历与文件扫描的并行调度 |
| `encoding_rs` | UTF-8 校验与 GB18030 解码（纯 Rust，无 C 依赖） |

参数解析与目录遍历均使用标准库实现。
